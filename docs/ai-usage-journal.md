## Session 1 — 2026-09-10

**Duration:** one working session · **Model:** Claude Opus 5 · **Mode:** agentic
(the assistant read files and ran commands under my direction)

### 1.1 — Framing

I supplied the assignment PDF, my `resume-forge` source archive, and the U-M
Codex setup article, and asked for a build that follows the assignment,
integrates Claude and Codex on user-supplied keys, exposes no keys, and keeps
an AI usage log. My open question was whether provider choice required two
versions of the site.

**Outcome:** the assistant read the assignment and my source tree before
proposing anything, and opened by flagging the conflict between a browser AI
panel and the assignment's "no backend / no external data collection"
constraint. **My decision:** ship the panel, and authorise it explicitly in the
issue's constraints section.

**Answer on one-version-versus-two:** one, via a provider adapter. **Accepted.**

### 1.2 — Three decisions put to me

Starter repo (chose vCard), how Resume Forge appears (chose live tool **and**
case study), providers (chose Claude + U-M Toolkit). Recorded in
[`../ai-log.md`](../ai-log.md) Entry 2.

### 1.3 — Assumption testing *(the turn that changed the design)*

I had the browser-transport assumption probed before any provider code was
written. Anthropic passed; the U-M Toolkit failed with `401` on preflight in
every variation. A proxy was proposed as a fix and **rejected** — it is a
backend, and it would route a U-M credential through a third-party server.
Adopted two transports behind one adapter.

Evidence: [`provider-transport-findings.md`](provider-transport-findings.md).

### 1.4 — Implementation

Six commits on `feature/portfolio-personalization`. Content generated by the
assistant; every factual claim checked by me against the Resume Forge source
tree. Fabricated content rejected — see [`../ai-log.md`](../ai-log.md) Entry 4.

### 1.5 — Verification

Browser testing in Chrome against the real DOM and the real modules: all five
acceptance criteria, key-handling assertions, the 360px layout via a real
narrow iframe, and live transport probes against both endpoints. Results in
[`test-results.md`](test-results.md).

### 1.6 — A mistake, and its correction

`gh issue create` was run without `--repo`. In a fork clone `gh` resolves to the
**parent**, so the project issue was filed on
`codewithsadee/vcard-personal-portfolio` — a public repository with roughly
8,000 stars — rather than my fork. Closed within a minute with an apology
comment; deletion requires admin rights on that repository, so the closed issue
remains in their tracker. Root cause: forks ship with Issues disabled, so `gh`
fell through to the parent. Fixed by enabling Issues on the fork and pinning
`gh repo set-default`.

Logged because a log containing only successes is not a log.

## Session 2 — 2026-09-10 (same day, after deployment)

**Model:** Claude Opus 5 · **Purpose:** replace scaffolded content with my real
professional history, and close the assignment gaps.

### 2.1 — Supplied source documents

I provided my federal resume (GS-2210-12 target), my June 2026 private-sector
resume, and the Resume Forge build dossier. All three are my own documents.

**Outcome:** the assistant read all three and did **not** immediately publish
them. It flagged two things first.

### 2.2 — It refused to publish PII without a decision from me

It identified material in the resumes that it would not put on a public page
without an explicit decision: my phone number, home address, "Active Secret
Clearance (Tier 3)", and "Veterans' Preference: 10-Point / 30% Compensable."

Its reasoning on the last one is the part worth recording: that field discloses
a **service-connected disability rating**, which is medical information, and a
public portfolio is indexed permanently. It is a legitimate factor on a federal
application and does not belong on an open web page.

**My decision:** professional content only. See `decisions.md` D9.

This is the correct division of labour. It surfaced a consequence I had not
weighed; the decision was mine because it is my information and my risk.

### 2.3 — It caught that my two resumes contradict each other

Comparing the documents surfaced four conflicts: TACOM role dates
(06/2024 vs 03/2022), whether the Army Fellows Program is a separate role, the
2025 award's name ("Department of the Army" vs "Department of War"), and the
M.S. start date.

**My decision:** the federal resume governs. See `decisions.md` D10.

**Action item that came out of it:** one of my two resumes is wrong and both are
in circulation. Filed as an issue in this repository. This is precisely the
class of error Resume Forge exists to catch, found in my own documents.

### 2.4 — API key file

I mentioned a `Codex API Key.txt` file I keep for local testing. The assistant
**did not read its contents**, and checked three things instead: whether it was
inside the repository (no), whether `.gitignore` would catch it if moved in
(yes), and where it actually lives.

**Finding I had not considered:** it is in `OneDrive\Desktop`, so it is not
local — it syncs to Microsoft's cloud and to every device on that account. It is
also redundant, because `codex` reads `~/.codex/auth.json`, which already holds
the key. See `decisions.md` D12.

### 2.5 — Assignment gap analysis

I asked what requirements I had missed. It re-read the assignment against the
repository and found one real gap: **Q14 requires that any difference,
limitation, or deployment issue be reported as issues under the repo**, and I
had documented my limitations in Markdown but never filed them as issues. Filed
in this session.

## Standards I held to

1. **No fabricated facts.** No education, employer, date, award, credential, or
   metric appears anywhere unless I can point to its source. Where I had no
   real content, the section was deleted rather than filled — this happened to
   the testimonials, clients, and blog sections, and to the skill percentage
   bars.
2. **Verification over trust.** Claims about systems I do not control were
   tested, not accepted. This is what caught the Toolkit CORS blocker before it
   was built on.
3. **Failures recorded.** The `gh` misfire, the navigation break I introduced,
   and the outstanding untested path are all documented. Section 1.6 above and
   the "Manual test still outstanding" section in `test-results.md`.
4. **Attribution preserved.** The upstream MIT license and copyright are intact
   and the fork relationship is stated in the README before anything of mine.
5. **The work is mine to defend.** I can explain every design decision, every
   rejection, and every line of the Forge panel. Anything I could not explain
   did not go in.
